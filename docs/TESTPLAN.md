# precinto — Test plan (v0.2)

Normative for every group. Maps tests to invariants (SPEC §18) and decisions (`docs/DECISIONS.md`), assigns each test to the group that owns the code under test (docs/OWNERSHIP.md), and fixes the fake-HOME conventions. A change that adds behaviour adds its tests in the same change.

**Test IDs.** Rows carry IDs in their own namespaces so they never collide with review findings (S…, R…, UX…, HA…, IM…), decisions (D…) or message IDs (C…, B…, D.shim): crash matrix `SEAL-n`, `REST-n`, `HIST-n`, `CODX-n`, `NOTE-n`, `LIVE-n`, `CONC-n`, `PERF-n` (§4); security `SEC-n` (§5); hook goldens `HOOK-n` (§6); end-to-end `E2E-n` (§9). The `Tests:` lines of docs/API.md and `internal/archtest/allowlist.go` cite these IDs.

## 1. Principles
1. **Never touch real user data.** No test reads or writes `~/.claude`, `~/.codex`, `~/Library/Application Support/precinto` or any real project. Every path comes from `internal/testkit` (or `t.TempDir()`), and `HOME` is overridden too.
2. **Synthetic content only.** Payloads, transcripts, rollouts and notes are generated by `claudetest`/`codextest` with marker strings from `testkit.Marker`. Golden files never contain real prompts, paths, emails, tokens or non-fixture UUIDs; `testkit.Hygiene` runs over every `testdata/` directory in CI (S13).
3. **Leak checks by marker.** Security and E2E tests grep the whole fake home (excluding `capsules/`) for markers after each scenario; any hit fails (I7).
4. **Deterministic time and processes, one time frame per boundary [D77].** State-machine and liveness tests use `fakeplatform.Clock` (independent wall and monotonic readings, `Sleep`, `StepWall`) and `fakeplatform.Procs` (start times, reuse, zombies, `SetCwd`, `SetOpenFiles`). A clock frozen at `testkit.Epoch` (`fakeplatform.NewClock`) is only for code whose every time input is fake; its fixture times derive from that clock, never from a copy of the date. Code that compares its clock with times the kernel stamps (mtimes of files and directories a test creates, real process start times) or that another component checks against the system clock runs on `fakeplatform.NewRealClock()` (the system clock plus what the test advanced) with fixtures stamped relative to it. A time sent to another process or over ipc — an unlock deadline above all — is real time whatever the clock (`time.Now`, a context deadline). No test may depend on the system clock's distance to a fixed date: frame tests run the liveness engine, the sweep, the daemon, the CLI and the hook with clocks frozen decades before and after Epoch and a year either side of the system clock. Real child processes are used only where the kernel behaviour is the subject (platform, wrapper PTY).
5. **External test packages** (`package foo_test`) by default; internal tests only for unexported helpers.
6. **Unit tests must not need build tags.** They construct layouts with `paths.LayoutAt`. Tags: `testing` (binary honours `PRECINTO_HOME`/`PRECINTO_RUNTIME_DIR`; `ipc.DialOptions.Insecure` allowed), `failpoints` (crash and errno injection).
7. **Helper programs** (scripted TUI child, fake harness executables, fake daemons) are `main` packages under the owner's `testdata/` directory (skipped by `internal/archtest`), built by the test with `go build`; new non-test packages need a lead contract change.
8. **Helpers never outlive their test [D81].** Helper processes carry a lifeline (an inherited pipe or stdin) and a hard lifetime, and exit when the test process goes away; every wait on a process is bounded (`exec.CommandContext`, `WaitDelay` when output is captured); every test kills and reaps every process it starts, including their sessions and descendants, and a package fails when a helper outlives it. A fake home is removed only after the daemons, binaries and workers started in it have exited: `test/integration` waits for every process running one of its binaries before each home's cleanup (`newHome`, `settleOwn`), `testkit.Settle` waits for processes holding files open below a home, and `testkit.ShortTempDir` waits for writers before it removes itself. A package that builds binaries calls `testkit.RemoveBinaries` from TestMain; after a completed run nothing of the tests is left in TMPDIR or `/tmp`.
9. **Scaffold-implemented helpers** (`paths` Env/Layout/Within/Tilde/LookPath, `config` Load/Save/Validate/RootFor/roots.list/Pinned, `ui.Format`, `fsx` Lstat/AppendLine/WriteFileAtomic/TryLock, `fsx/failpoint`, `capsule.UnitKey`/`GenName`, `platform.Ancestors`/`Descendants`, `harness.UnitKeyFor`, `ledger.Taint`, `sweep.MarkerText`) ship with their tests; owners extend them, never weaken them.

## 2. Fake HOME conventions (`testkit.NewHome`)
```
<t.TempDir()>/
  home/                         HOME
  home/work/acme/               protected root (config id "root-acme")
  base/                         PRECINTO_HOME
  claude/                       CLAUDE_CONFIG_DIR
  claude-tmp/                   CLAUDE_CODE_TMPDIR (0700)
  cache/claude-cli-nodejs/      Claude cache (via HOME/Library/Caches on darwin, XDG_CACHE_HOME on linux)
  codex-user/                   the user's CODEX_HOME (never ~/.codex)
  xdg/{data,state,cache,config} XDG_* variables
/tmp/pt-XXXXXX/                 PRECINTO_RUNTIME_DIR (short path: sun_path < 104 bytes; testkit.ShortTempDir)
```
- Per-root Codex homes live under `base/homes/codex/<root-id>/`, created by the code under test.
- `testkit.Home.Env` carries all variables; `Setenv(t)` applies them for tests that exec the binary. Binaries for integration tests come from `testkit.BuildBinary(t, "testing")` (or `"testing","failpoints"`).
- `testkit.Home.Env` also sets `PRECINTO_TEST_ANCESTRY_STOP` to the test process (`PID:START`, D64): in `-tags testing` builds the agent-context ancestry walk of `ui.AgentContext` and of the daemon's peer checks stops there, so suites run from inside a Claude Code or Codex session can `init` and unlock; env markers and the no-controlling-terminal rule still apply, and production builds never read it (SEC-33).
- Tests that run `precinto hook` give it a `testkit.ShortTempDir` `HOME`: hook mode ignores `PRECINTO_*` in every build (`paths.HookLayout`, D56), so its base and run directory come from `HOME` alone.
- Crash tests that run the binary set `PRECINTO_CRASHPOINT`; `cmd/precinto` reads it through `internal/paths` (`paths.EnvCrashpoint`) and calls `failpoint.Set` before dispatching, in `-tags failpoints` builds only. In-process tests call `failpoint.Set`/`Reset` directly.
- **Hooks never take a binary from the environment** (D56): to make a real harness run the testing build, E2E tests give the harness a throwaway `HOME` (plus `XDG_DATA_HOME` on linux) whose `<base>/bin/precinto` links to `testkit.BuildBinary(t, "testing")`, or load a test-only plugin directory with a generated shim. `PRECINTO_BIN`/`PRECINTO_DEV` must have no effect (SEC-12, SEC-31).
- Tests that need the daemon use `agenttest.Start` (in-process: fake clock and process table, no hardening, workers recorded by `Spawned` instead of executed, console state from `SetScreen`) or the built binary's `agent --foreground` with `PRECINTO_RUNTIME_DIR`.
- E2E tests that run a real `claude` with a throwaway `CLAUDE_CONFIG_DIR` set `CLAUDE_SECURESTORAGE_CONFIG_DIR=""` so the existing login keychain item is reused (no transcript of the user is read); they run only with `PRECINTO_E2E=1` and use `--model haiku`. The sandbox HOME is realpath'd (on macOS `/tmp` is a symlink, and harnesses report resolved working directories). `PRECINTO_E2E_CLAUDE` and `PRECINTO_E2E_CODEX` (absolute paths) choose the harness binary when several installs exist (a native Claude Code and an old npm one, say); each test logs the binary and its `--version`. On macOS a throwaway HOME can hide the login item: Claude then stops every prompt that passes the gates with its own login error before any model call. The gates run before the model, so E2E-1 (sealing after exit), E2E-2, SEC-13 and the UserPromptSubmit and SessionStart replays are still checked; the checks that need the model's answer (Claude answering outside a folder, the tool and permission replays) are skipped with a log line unless `ANTHROPIC_API_KEY` is set.
- Codex is never run against a real home: E2E uses a synthetic `CODEX_HOME` (and the per-root homes precinto creates); `codex exec --ephemeral` only where a real binary is required.

## 4. Crash-injection matrix
Tooling (G1): failpoints in every mutating `fsx` call plus phase points in callers, from the registry below; `PRECINTO_CRASHPOINT=<name>[:<n>]` SIGKILLs the process at the n-th hit; `<name>=errno:<E>[:<n>]` injects ENOSPC/EACCES/EPERM/EIO. Power-loss mode (G1 helper `internal/fsx/fsxtest`, `-tags failpoints`; G4 tests): `fsxtest.Record` records operations through `failpoint.ObserveFS`, `Recording.Images` rebuilds images keeping only data and renames covered by the last FullSync of each file/directory plus random dependency-closed subsets of later operations, and the test runs recovery on each image.

**Failpoint registry** (lead-owned: a name is added here before it is used, and each name is hit in exactly one place, so `:<n>` hit counts are meaningful):

| Point | Hit by (owner) | Where |
|---|---|---|
| `fsx.write`, `fsx.fsync`, `fsx.rename`, `fsx.unlink`, `fsx.readdir`, `fsx.link` | `internal/fsx` (G1) | before every mutating syscall of that kind |
| `capsule.tmp_written`, `capsule.verified`, `capsule.renamed` | `capsule.Seal` (G1) | right after each milestone inside Seal (never a `seal.*` name) |
| `capsule.streamed:<n>` | `capsule.Seal` (G1) | in pass 2, after the n-th input is streamed into the temporary |
| `seal.prepared`, `seal.tmp_written`, `seal.committed`, `seal.unlinking:<n>`, `seal.rescue`, `seal.receipt` | `internal/sweep` (G4) | right after the journal milestone of the same name (including from sweep's own `OnPhase` callback) |
| `seal.logged` | `internal/sweep` (G4) | right after the capsule-log append, before `committed` is journaled (there is no `seal.renamed`: the only commit rename is Seal's own, `capsule.renamed`) |
| `restore.staged`, `restore.placing:<n>`, `restore.receipt` | `internal/sweep` (G4) | right after each restore milestone / placed file |
| `history.held`, `history.sealed`, `history.renamed`, `history.tail:<n>` | `internal/sweep` (G4) | after each history milestone; `history.renamed` between the rename of `history.jsonl` and the `rewritten` milestone (HIST-3); `history.tail` between the tail append and the offset save |
| `codex.blob:<n>`, `codex.manifest` | `internal/sweep` (G4) | after each blob commit / before the manifest rename |
| `journal.save` | `internal/sweep/journal` (G4) | before each record write |

Writer simulators (G3): `claudetest.StartAppender` (open/append/close every 10–50 ms, recreates the file), `codextest` writer lock holder and an O_APPEND writer; SQLite files are opaque byte groups (no driver is linked).

Checks after recovery + one sweep, for every row: **O1** no loss (every byte version placed or observed is recoverable from plaintext + decrypted generations); **O2** no duplicate JSONL uuids after restore; **O3** resumable (Claude: parentUuid chain intact; Codex: each db and its wal come from the same generation — byte comparison of the group); **O4** dwell (no plaintext for non-live units of locked folders unless listed unsealable with a reason); **O5** no clobber (pre-existing plaintext byte-identical or kept as a generation/conflict copy); **O6** recovery is idempotent; **O7** no false alert (precinto's own crash leftovers are never quarantined or reported as forgeries).
