# Design decisions (ADR log)

Each entry: ID · decision · why · status. *Status* `default` = chosen by the design assistant as a safe default after the v0.1 spec review (2026-11-21) and pending confirmation by the project owner; `owner` = confirmed by the owner.

Review inputs: five adversarial spec reviews (security, reliability, UX, harness-compat, implementability) and two research rounds (14 agents), see `docs/research/` (not committed: lives in the private workspace).

## Keys and cryptography
- **D1 · One identity per protected root** ("one KeePass database per folder"). Global units (Claude history rotation, other global stores) belong to a special `global` vault. Unlocking a root unwraps only that root's identity. *Why:* makes per-root isolation real; an agent working in root A cannot get B's key. *default*
- **D2 · Classic X25519 for v0.1** (no hybrid PQ). *Why:* the wrap of every identity by Secure Enclave/YubiKey is classic anyway (age-plugin-se PQ tags are buggy in 0.2.1), so PQ capsules would not resist a quantum attacker; X25519 keeps interop with the `age` CLI. PQ is a roadmap item once factor wraps can be PQ. *default*
- **D3 · Default factors**: macOS → `se` (age-plugin-se, `any-biometry-or-passcode`; never biometry-only) + recovery. Linux → passphrase + recovery (plugins optional). Passphrase factor optional on macOS, min 12 chars, scrypt work factor 2^20, `doctor` warns it is offline-attackable. *default*
- **D4 · Daemon-side unwrap with client-relayed UI.** The daemon (autostarted from the user's terminal session, not a LaunchAgent) runs the age plugin / scrypt; plugin `ClientUI` messages and passphrase requests are relayed to the requesting client's TTY, or to `pinentry-mac`/`pinentry-gnome3` when the client has no TTY (hooks). The unwrapped identity never leaves the daemon. *default*
- **D5 · Authenticated recipient set.** Per root, `vault.toml` stores recipients plus `recipients_mac = HMAC(HKDF(identity, "precinto/recipients/v1"), canonical set)` written while unlocked. Unlock verifies `identity.Recipient() == vault recipient` and the MAC; mismatch ⇒ refuse grant + alert. The sealer refuses to seal (exit 5, plaintext kept) if `vault.toml` recipients differ from `state/verified/<vault-id>.recipients` (the tripwire copy written by the daemon after a successful verification). Every manifest carries `recipients_fpr`; unlock audits capsules sealed since the last audit. After writing a capsule the sealer parses the age header and requires exactly the expected stanza count/types. Recovery from a mismatch: `precinto vault repair` [D53]. *default* (file name amended 2026-11-21)
- **D6 · Mutual socket authentication.** Client checks the socket dir (owner, 0700, no symlink) and that the server pid's executable is the same file (dev+inode) as its own; daemon checks peer uid. Daemon holds `run/agent.lock` (flock) for its lifetime. Secrets travel as length-prefixed binary frames, never JSON strings. Production builds ignore `PRECINTO_HOME`/`PRECINTO_RUNTIME_DIR` unless built with the `testing` tag or `PRECINTO_DEV=1` *and* not in an agent context. There is no `PRECINTO_BIN`: the hook shim never reads `PRECINTO_*` variables, because hooks always run in an agent context and Claude's settings `env` (agent-writable in `<root>/.claude/settings.local.json`) reaches hook processes; tests point `<base>/bin/precinto` at the testing build through a throwaway `HOME` instead [D56]. *default* (amended 2026-11-21)
- **D7 · Recovery key is shown only to a human.** `init` refuses to print it when stdout is not a TTY or when running under an agent (CLAUDECODE, CODEX_* env, or harness in the process ancestry); offers `--recovery-out FILE` (0600) instead; requires typing back the last 4 characters. `precinto recover --verify` checks it decrypts a fresh capsule. *default*

## Capsules, provenance and restore
- **D8 · Capsule log + derived targets.** Every sealed capsule is appended to `state/capsules.log` (ciphertext and header SHA-256, kind, **unit key**, vault and root ids, generation); unit ids (sid, slug, relpath) exist only inside ciphertext [D45]. Restore accepts only logged capsules, takes the unit id from the decrypted manifest and accepts it only if `harness.UnitKeyFor(salt, kind, harness, registered home id or root id, unit id)` equals the logged unit key — otherwise the whole capsule is rejected (exit 5) before any write — and then computes allowed target paths from (kind, harness, authenticated unit id, registered home, root, config), never from manifest paths, which must merely fall inside those bases. *default* (amended 2026-11-21)
- **D9 · Generations, never overwrite.** Units are stored as `<unit>.g<N>.pcap`; a new generation never replaces an older one in place. Keep the last 3 generations, and keep any generation whose content is not a prefix of its successor ("diverged") until the user prunes. Restore uses the newest. *default*
- **D10 · Lineage check at re-seal.** At restore the restoring client (wrapper/CLI/worker, D39) records identity, size and SHA-256 of each placed plaintext file in `state/receipts/<unit-key>.json`. At re-seal: unchanged ⇒ delete plaintext, no new generation; append-only file whose first `size` bytes hash to the recorded value ⇒ new generation supersedes; otherwise ⇒ new generation marked `diverged`, old kept. After a commit the sealer rewrites the receipt to the new generation for files still present [D58]. *default* (amended 2026-11-21)
- **D11 · No blind concatenation.** If plaintext already exists where a restore would write: superset of the capsule ⇒ keep plaintext; classic Claude fragment (disjoint `uuid`s, first `parentUuid` inside the capsule) ⇒ JSONL merge by `uuid` (capsule lines, then new lines); anything else ⇒ restore to `<name>.precinto-restored`, leave plaintext untouched, report a conflict (`precinto merge` resolves). *default*
- **D12 · Restore is unit-atomic.** Stage the whole unit in a 0700 staging dir on the same filesystem (free-space check first), then rename into place file by file under the unit lock, with a journal so a crash resumes or rolls back. All file operations use directory file descriptors with `O_NOFOLLOW` (no symlink traversal, no TOCTOU). *default*
- **D13 · Two-pass sealing.** Pass 1 hashes files and builds the manifest; pass 2 streams manifest + files, re-hashing while streaming; any mismatch aborts (file still changing). Then ephemeral round-trip verification, header check, fsync, rename, re-stat, delete. *default*
- **D14 · Claude retention vs restore.** Sessions older than `cleanupPeriodDays − 2` are not part of the automatic "recent" restore; explicit `precinto resume <id>` restores them with mtime clamped to `now − 1 day` so Claude's sweep keeps them. Capsules are never deleted at restore, so a file deleted by the harness sweep is not lost. *default*
- **D15 · Capsule retention.** Keep forever by default; `precinto prune` is manual. Harness deletions (`claude purge`, `codex delete`, retention sweeps) are not mirrored. *default*

## Markdown
- **D16 · Markdown capsules live in the store**; the working tree keeps only a small text marker `<name>.md.precinto` (no ciphertext) with the capsule id and how to open it. Losing the marker (git clean, checkout) loses nothing; `precinto ls --root` lists sealed notes. Restore target = marker location minus suffix, inside the root. *default*
- **D17 · Markdown is sealed only when no session in the root is busy** (after `busy_grace`), never under a running turn. Git-tracked files and instruction files are never sealed by default. Bash-created Markdown requires `md = "all"`. *default*

## Liveness and concurrency
- **D18 · Liveness = union of signals, measured by precinto itself.** Live if: precinto ledger shows the session current for a pid that is alive with the *same start time as measured by precinto* (sysctl/proc), and that pid has not moved to another session (SessionEnd reason clear/resume + newer start); or a Claude registry file mentions the sid with a live pid whose start time ≤ `startedAt` (+2 s); or a wrapper live-lock (flock) is held; or a Claude job state mentions the sid; or any unit file changed within the quiet window (120 s). Malformed registry with live pid ⇒ treat that pid's cwd sessions as live. *default*
- **D19 · Transcripts are located by session id**, across all project dirs, including `*.superseded-*` and `*.compact.tmp.*` siblings; never by cached path or inode. *default*
- **D20 · Non-current transcripts of a live process are sealable** (after /clear or /resume the old sid is no longer current: SessionEnd reason clear|resume, newer ledger start for the same pid, or registry sessionId differs, plus quiet window). *default*
- **D21 · history.jsonl rotation** only when no Claude process is running anywhere (process-table scan by executable, not just the registry), with tail-reconcile before the atomic rename and journaled offsets after it [D58]. Paste-cache entries referenced only by extracted lines move into the same capsule. *default*

## Lock model
- **D22 · Gate hooks fail closed** (Claude `onFailure: block`, explicit timeouts: UserPromptSubmit 90 s, PreToolUse/PreCompact 10 s; internal deadline below the timeout; always emit valid harness JSON). The plugin shim reads `roots.list` so a missing or failed binary blocks only inside protected roots [D56]. Requires Claude Code ≥ 2.1.295. *default*
- **D23 · Idle clock resets only on human input**: wrapper keystrokes, and UserPromptSubmit whose daemon-computed origin is `human` [D54]. Stop/StopFailure/Interrupt clear *busy* but never extend the unlock. Busy also expires after `busy_timeout` (10 min without hook activity and registry not busy). *default*
- **D24 · Screen lock**: soft lock immediately; hard-lock idle sessions after `screen_lock_hard_after = 15m` of continuous screen lock; busy sessions get `busy_grace = 30m`, then hard lock. `max_unlock` (8 h) ⇒ soft lock. Sleep/wake ⇒ soft lock at wake. *default*
- **D25 · Background/supervised Claude sessions** (`--bg`, agent view, daemon backend) are exempt from hard lock (the supervisor would restart them); they stay gated by soft lock and are flagged in `status`. *default*
- **D26 · Automated prompts during soft lock** (/loop, scheduled tasks, cross-session messages) are blocked like human prompts and never raise an unlock dialog. *default*
- **D27 · Unlock UI by context**: hooks (no TTY) may only use GUI-capable factors (SE, plugin with GUI, pinentry); otherwise they block with "run `precinto unlock` in a terminal". Prompts are rate-limited (3/min, 30 s back-off after cancel); the reason text of pinentry and passphrase prompts is built by the daemon from verified data (the `se` dialog text belongs to age-plugin-se, D60). *default* (amended 2026-11-21)
- **D28 · Agent-context requests.** When the requesting process descends from a harness (ancestry or env) — or, for `cat`, `open`, `restore --all` and `ls` titles, has no controlling terminal and is not a daemon worker [D59] — content-revealing operations (`cat`, `open`, `restore`, `ls` titles, `export`) need fresh user presence even when the folder is unlocked; unlocking any folder other than the one of the session it runs in is **refused** (C12.agent, no dialog); `init`, factor, recovery, `vault repair` and destructive operations (`prune`, `forget`, `unprotect`) are refused. *default* (amended 2026-11-21: "unlock of another root" is refused, not presence-gated, matching SPEC §12.8)
- **D29 · `on_enter = "prompt"`** (the owner explicitly asked for a forced unlock when entering a protected folder). Guarded: interactive top-level shells only, only on outside→inside transitions, rate-limited, Ctrl-C skips; the real enforcement is the pre-launch gate. *default*
- **D30 · Wrapper soft-lock screen**: clear screen and scrollback, keep the child output in wrapper memory — a bounded ring of **all output since the child started**, not only output produced while locked [D60] — show the lock overlay, block input; on unlock replay the ring from a safe boundary and force a redraw (resize cols−1, then cols). *default* (amended 2026-11-21)

## Harness scope
- **D31 · Codex uses per-root homes**: `precinto run codex` inside a protected root sets `CODEX_HOME=<base>/homes/codex/<root-id>`, seeded from `~/.codex` (config.toml copied, auth.json synchronized back on exit, plugins/skills linked). Outside roots Codex is unmanaged. A Codex session in a protected root without the per-root home is refused by the gate hook (when hooks are trusted) and flagged by `doctor`/`status` (`codex-wrong-home`: rollouts in the user's own Codex home whose recorded cwd lies inside a root — only that field is read). Whole-`~/.codex` sealing is dropped; such rollouts stay unsealed (SPEC §19). *default* (amended 2026-11-21)
- **D32 · Claude settings via the wrapper**: `precinto run claude` passes `--settings` with `idleCompaction:false` and `awaySummaryEnabled:false` for protected roots; precinto never writes into user repos unless `protect --claude-settings` is used. *default*
- **D33 · Other harnesses**: data-driven inventories ship as `experimental`, wrapper-only (home relocation via each harness's env var where available), liveness by wrapper lock + `lsof` on store files + quiet window. *default*
- **D34 · Platforms**: macOS first (screen-lock/sleep triggers, SE). Linux builds, with idle timers and `loginctl LockedHint` polling. No Windows in v0.1. *default*
- **D35 · Distribution**: build from source (`go install`, Homebrew formula from source) until signing/notarization is decided by the owner. The repo stays private until the owner decides to publish it. *default*

## Added with spec v0.2 (architect, 2026-11-21)
Proposed while writing SPEC v0.2 and the Go contract; same status semantics as above.
- **D36 · Per-root history capsules; the `global` vault holds only unattributable stores.** Lines extracted from Claude's `history.jsonl` (and the paste-cache entries only they reference) are sealed to the vault of the deepest root containing their `project`; the `global` vault [D1] holds `usage-data/`, `feedback/drafts/` and other global content that names no root. Merge-back appends missing lines byte-for-byte (idempotent, never a rewrite). *Why:* sealing every root's history to one global key would expose root B's prompts whenever A is unlocked, defeating D1. Refines D1. *default*
- **D37 · Prompt origin heuristic.** A UserPromptSubmit is `human` if, in a wrapped session, an Enter keystroke reached the PTY ≤ 3 s before the hook, or, unwrapped, the system HID idle is ≤ 5 s at hook time; otherwise `automated`; `unknown` when HID idle cannot be read — it **never moves the idle clock** and never raises an unlock dialog [D54]. Only the daemon computes the origin. *Why:* makes D23/D26 implementable; the payload has no origin field. *default* (amended 2026-11-21: `unknown` no longer counts for the idle clock)
- **D38 · Restore budget.** `restore_recent = 5`, `restore_max_bytes = 1 GiB`; the targeted units restore synchronously before exec, the rest in the background newest-first; free-space floor max(2 GiB, 5 % of the volume). *Why:* restoring 20 multi-GB sessions before launch is slow and widens plaintext exposure. *default*
- **D39 · Client-side restore with per-capsule file keys.** Restore runs in the wrapper/CLI/worker (the harness's environment and TCC context); the daemon releases per-capsule file keys — never identities — only to peers running the same precinto executable, only for capsules in the capsule log (provenance key: age header SHA-256 + path), only when every root of the capsule is unlocked, subject to D28. *Why:* keeps multi-GB I/O and the wrong environment out of the key holder; consistent with D4 (the identity never leaves the daemon). *default*
- **D40 · Multi-folder unlock costs one presence prompt per folder.** `unlock --all` lists the folders, asks for typed confirmation on a TTY, then prompts once per folder; `per_root_auth = false` makes `unlock` cover every folder that way and share one idle clock. No bundled wraps in v0.2. *Why:* bundles would put all keys behind one prompt and complicate adding roots; revisit with a bundle design. *default*
- **D41 · Plugin layout.** Claude, Droid, Cursor and Copilot share `plugin/` (one manifest per vendor); Codex ships from its own byte-stable root `plugins/codex/` (manifest, `hooks/codex.json`, shim) listed in `.agents/plugins/marketplace.json`, with a frozen plugin version. Cursor and Copilot manifests are experimental. No `unlock` markdown command. `codex.json` uses only the handler keys of Codex 0.154 — no `onFailure` — and brace-less `"$PLUGIN_ROOT/…"` commands, and is frozen only after the opt-in Codex E2E passes under sh, bash, zsh and fish [D61]. *Why:* Codex's trust hash covers every file of the plugin root; any release edit would silently disable its hooks (HA18). *default* (amended 2026-11-21)
- **D42 · Generation lineage and restore semantics.** Each generation records `fresh|successor|partial|diverged` against the receipt. Layered kinds (Claude units, notes, generic) restore the newest generation plus, through non-successor links, files of older generations absent from newer ones (version collisions go through the placement table [D11]; unresolvable ones keep the newest at the path and older ones as `.precinto-g<k>` copies). Snapshot kinds (Codex home) restore exactly the newest snapshot. *Why:* operationalizes D9/D10 without losing files to partial re-seals or resurrecting deleted SQLite WALs. *default*
- **D43 · Hook exit-code contract.** The binary exits 0, 10 (intended "exit 2" block) or 1. The shim passes stdout through on 0, maps 10→2, and treats every other exit (1, a Go runtime exit 2, a signal) like a missing binary: it discards stdout and applies the `roots.list` rule — static block inside a protected root, exit 0 outside [D56]. Claude blocks with decision JSON and exit 0; Codex UserPromptSubmit/PreToolUse/PermissionRequest block with a fixed stderr reason and exit 2; Codex PreCompact with `{"continue":false}` and exit 0. *Why:* Go panics exit 2, Claude's plugin exit-2 exemption, and Codex login-shell noise would otherwise open or misfire gates (HA5, HA6); a crashing binary must not block Claude in every directory. *default* (amended 2026-11-21)
- **D44 · Codex per-root home details.** The wrapper also sets `CODEX_SQLITE_HOME` and `TMPDIR` inside the per-root home; `config.toml` is copied once with `sqlite_home`/`log_dir` removed (`precinto codex sync-config` re-seeds); `auth.json` is synced in when newer and back after exit; plaintext that diverged from the newest snapshot makes `run codex` refuse until `precinto codex reconcile`. Refines D31. *default*
- **D45 · Naming.** Unit keys are `HMAC-SHA256(per-install name salt, kind|harness|home id|…|unit id)` truncated to 128 bits; capsules live at `capsules/<harness>/<unit-key>/g<N>.pcap` (realizes D9's `<unit>.g<N>.pcap`); generation numbers come from fsynced counters, never clocks; precinto never computes Claude slugs. *Why:* no guessable plaintext names (S13), stable ordering, relocation-proof (HA15). *default*
- **D46 · Claude plans are their own units**, keyed by the slug recorded in transcripts and live while any live session references the slug. *Why:* forks and branches share plan slugs (R21). *default*
- **D47 · Claude project units (auto memory, MCP logs, legacy index) seal only when no Claude process has a cwd inside the root, inside the git repository containing it, or an unknown cwd.** *Why:* memory is shared by every session and worktree of a repository (R10, HA14). *default*
- **D48 · Policy pinning.** The daemon enforces the policy confirmed at the last interactive unlock, persisted in `state/policy.pinned` [D55]; config edits that weaken protection stay pending until an interactive unlock shows the diff and the user confirms; strengthening edits apply at once; hooks use the stricter of `config.toml` and `roots.list`. *Why:* any same-UID process (including the agent) can edit config.toml (S16). *default* (amended 2026-11-21)
- **D49 · v0.2 scope.** Deferred: `canary`, `scrub`, `rekey`, `import`, Claude mods, incremental Claude capsules, PQ (D2), Linux systemd unit and D-Bus triggers (polling only; `service install` is darwin-only in v0.2 and exits 2 with a notice on linux), Windows. In scope: claude-code and codex native, generic inventories experimental (D33), `resume --pick`, `vault repair` [D53]. *Why:* the review found the v0.1 surface too large to implement safely in parallel (IM10, IM24). *default* (amended 2026-11-21)
- **D50 · `precinto lock` with no flag locks every folder** (KeePass "lock workspace"); `--root` narrows it; `--end` (alias `--hard`) also ends sessions; user-facing words are "locked", "paused", "ended and sealed". *Why:* a predictable default and a vocabulary users understand (UX16). *default*
- **D51 · Markdown restore without a marker.** When a note's marker is gone, the note restores at its original relpath, authenticated by its unit key, and the user is told (C11.restored). Refines D16 (marker location wins when the marker exists). *Why:* `git clean` must not lose or orphan notes (UX8). *default*
- **D52 · Ungated sessions at lock.** A session that cannot be paused — no precinto hook event observed (plugin disabled, `--bare`, `disableAllHooks`, untrusted Codex hooks) or a host that cannot gate prompts — gets the lock screen when wrapped. Unwrapped, it is found by the daemon's process-table scan (inventory executable, cwd inside a locked root, no hook event or registration for that ProcID within the hook-presence window) and is **ended at lock only when it is an interactive Claude session** whose registry entry is readable and not background/supervised; every other match (Codex, generic, unreadable registry, unknown cwd) is **reported in `status`**, never signalled [D57]. Background sessions stay exempt (D25). *Why:* without a gate, "locked" would protect nothing for that session (S4, S19); signalling on weak evidence could kill the wrong process. *default* (amended 2026-11-21)

## Added in the v0.2 fix pass (architect, 2026-11-21)
Proposed while applying the verifier's findings on SPEC v0.2 and the scaffold; same status semantics.
- **D53 · Vault repair.** `precinto vault repair --root DIR | --global [--recovery]` (TTY only, refused in agent contexts) is the recovery path after a recipients MAC mismatch or tripwire refusal: the daemon unwraps the identity with a factor (or, with `--recovery`, from `identity.recovery.age` with the typed recovery key), requires it to open the header of at least one capsule of that vault logged before `last_audit` (when any exists; otherwise C14.notgenuine and nothing changes), shows the recipient diff, asks for typed confirmation (C14.confirm), then rewrites `recipient`, `recovery_recipient` (from the recovery identity, or kept only if it equals the verified copy — else `ErrNeedRecovery`), the MAC and the tripwire copy, and lists capsules sealed since `last_audit` with a foreign `recipients_fpr` as exposed. The `vault-tampered` attention item names the command. *Why:* without it one tampered `vault.toml` stops sealing for that folder forever, so plaintext accumulates and G1 breaks (S1). *default*
- **D54 · Activity is authenticated by the daemon.** The daemon ignores any origin a client claims (the field is gone from `ipc.ActivityReq`): it records the origin it computed when answering a UserPromptSubmit gate for (sid, prompt/turn id), and a later `activity prompt` moves the idle clock only if that recorded origin was `human`. `input`/`enter` activity is accepted only from a same-executable peer whose measured ProcID equals the session's registered wrapper (a `register` with `wrapper=true` is accepted only from the wrapper itself). `unknown` never moves the idle clock, so headless Linux without HID idle relies on wrapper keystrokes, idle timers and `max_unlock`. *Why:* any same-UID process could otherwise keep a folder unlocked until `max_unlock` (S5). Refines D23, D37. *default*
- **D55 · Pinned policy is persisted.** At each TTY-confirmed unlock the daemon writes `state/policy.pinned` (the confirmed configuration plus one MAC per vault unlocked at that moment, `HMAC(HKDF(identity, "precinto/policy/v1"), canonical config)`). At start it enforces the stricter of `config.toml` and the pinned file; when a vault listed in the file is unlocked it verifies that vault's MAC; a missing or bad MAC raises `policy-tampered` and the daemon also takes the compiled-in defaults into the strictest merge until the next TTY confirmation. *Why:* a daemon that exits after 10 min idle would otherwise adopt a tampered `config.toml` as its new baseline (S16). Refines D48. *default*
- **D56 · Host detection and shim failure rule.** The hook's host is identified by other hosts' markers first, then Codex markers (`turn_id`, or `PLUGIN_ROOT` with label `codex` or without `CLAUDE_PID`/`CLAUDECODE`), then Claude markers (`CLAUDE_PID`, `CLAUDECODE=1`, `CLAUDE_PROJECT_DIR`), and otherwise defaults to the argv label (the hooks file that invoked it); a missing marker never makes a gate fail open. The shim never reads `PRECINTO_*`, passes stdout through only on exit 0 (10 → 2), and treats any other exit like a missing binary (static D.shim block inside a `roots.list` root, exit 0 outside). `doctor` flags `PRECINTO_*`, `HOME`, `XDG_*`, `PATH` and loader variables in the `env` of Claude settings files. *Why:* `CLAUDE_PID` was never observed on PreToolUse/PreCompact/PermissionRequest and Codex SessionStart/SessionEnd carry no `turn_id` (HA3, HA5, S4); settings `env` reaches hooks (S2); a crashing binary must not block every Claude session everywhere. Amends D6, D43. *default*
- **D57 · Ending sessions safely.** Session-wide kills (`platform.SignalGroup`) are used only for sessions precinto created: the wrapper's PTY child and direct-mode children, which are started with `Setsid` (signals forwarded by the wrapper). For an unwrapped harness precinto signals only the ProcID-verified harness process and its ProcID-verified descendants found by walking PPIDs (`platform.Descendants`), never by session or process-group id — an unwrapped `claude` shares the user's terminal session. Unregistered ungated processes are found by the scan of D52; only interactive Claude matches are signalled. *Why:* `kill` of "the remaining processes of its session" would kill the user's login shell and every job of that tab (R11). Amends D52. *default*
- **D58 · Crash-safety refinements.** (a) Journal phases are completed milestones persisted after their step; everything recovery needs for the next step — for a seal the temporary and the final `g<N>.pcap` name — is journaled before that step. (b) Recovery of `prepared`/`tmp_written` removes the temporary and an unlogged capsule of the recorded name (it cannot be re-verified: the ephemeral key is gone); generation numbers may have gaps; `committed`/`unlinking` recovery first requires the capsule to exist and be logged. Quarantine runs only after recovery and never touches journal-named capsules, so precinto's own crash leftovers are never reported as forgeries. (c) After a commit the receipt is rewritten to the new generation for every file still present and deleted only when none remains, so a remove-failed unit re-seals as `unchanged`. (d) A lock during restore destroys file keys at once, rolls back a unit not yet staged and rolls forward a staged/placing unit from staging. (e) History rotation journals the hold offsets (`S0`, `S1`, `offset`, `pending`, `new_base`); the tail loop reads `[offset, EOF)` and appends kept lines with line-union semantics, so nothing is appended twice. *Why:* R5, R6, R7, R15 of the verification pass; I9 and D36 idempotence. Refines D9, D10, D12, D21. *default*
- **D59 · Destructive operations and TTY-less peers.** `prune` (except `--dry-run`), `forget` and `unprotect` require typed confirmation on a TTY (C12.typed) and are refused in agent contexts. A peer without a controlling terminal (setsid, double fork, `env -i`) that is not a worker the daemon spawned counts as an agent context for the explicit content-revealing operations (`cat`, `cat --to`, `open`, `restore --all`, `ls` titles; key purposes `cat`, `open`, `restore-all`, `list`) and for the refusals of D28; targeted restores (wrapper launch, post-unlock worker) keep working without a terminal. Typed confirmations stop accidental and naive agent actions, not a process that allocates its own pseudo-terminal (documented in SPEC §19). *Why:* S8, UX6; ancestry checks alone are defeated by reparenting. Amends D28. *default*
- **D60 · Lock-screen replay and hook-raised dialogs.** The wrapper keeps a bounded ring (8 MiB) of all child output since start and replays it from a safe boundary at unlock (tail plus forced repaint when it wrapped; older output is not redrawn, SPEC §19). Before a hook-raised unlock dialog the daemon sends `OSC 9` with C2.hook to the session's TTY (recorded at register, or the harness process's controlling terminal, opened `O_WRONLY|O_NOCTTY` only if owned by the user). The `se` dialog text is age-plugin-se's. `unlock_on_prompt` ships `false` and flips to `true` only once the hook-dialog E2E passes on the pinned Claude version. `init` offers a passphrase factor (B.remote) when `$TMUX`, `$STY` or `$SSH_CONNECTION` is set. *Why:* UX3, UX4, UX6. Amends D27, D30. *default*
- **D61 · Codex hooks file before freezing.** `plugins/codex/hooks/codex.json` uses only the 0.154 handler keys (`type`, `command`, `timeout`, `async`) and `sh "$PLUGIN_ROOT/scripts/precinto-hook" …` (no braces: fish rejects `${VAR}`).
